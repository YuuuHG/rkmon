# 架构设计讨论

> 面向「别人的设备上装的服务跟我完全不一样」这个问题，以及安全与轻量化的取舍。
> 本文区分**已实现**、**已规划**、**仅设计**，不把设想写成既成事实。

## 1. 问题不是「少几个组件」，而是数据模型不对

旧监控页按服务分区：`实时性能 / 趋势 / Immich / 存储与系统`。这在单一设备上很整齐，
但换一台机器就会同时暴露三个问题：

1. 没装 Immich 的机器，整个分区显示「断」；
2. 用户想加的监控对象（PikPak 队列、风扇 PWM、磁盘 IO）不属于任何既有分区；
3. 分区把组件钉死在一行里，三个组件时列宽算法崩掉，拖拽也无从谈起。

所以第一步不是改 CSS，而是把数据模型从**按服务组织**改成**按指标组织**：

```
Metric { Key, Value, Unit, Type, Ts, Status }
Component = { 一组 Metric Key + 图表类型 + 尺寸/坐标 }
Service   = 只是 Metric 的来源标签，不再是布局约束
```

「不按服务分区」与「用户自建组件」只有在按指标组织时才不互相打架。

## 2. 采集抽象：为什么是混合而不是纯接口 / 纯 YAML

| 方案 | 优点 | 致命缺点 | 判定 |
|---|---|---|---|
| A 纯统一 Probe 接口 | 可插拔、易测、超时隔离 | 差异太大时接口膨胀成「上帝接口」 | 不单独用 |
| B 纯声明式 YAML/JSON | 最轻、用户加组件零代码 | 写不出 Postgres SQL、进程 argv、速率差分 | 不够用 |
| **C 混合（采用）** | 核心 `Probe → []Metric`，外层 manifest 声明端点/字段/组件绑定 | 需要维护一份 schema | ✅ |

具体分层：

- **核心**：`ServiceProbe` 有 `Name / Loop / Snapshot` 三个方法，每个 probe 独立 goroutine、
  独立超时，结果合并进 `now.<name>`。主循环 1 秒采样不等待任何外部服务。
- **声明层**：`probes[]` 配置端点、凭据文件、字段白名单、刷新间隔、关联组件。
  新增一个 HTTP 类服务 ≈ 加一段 JSON，不用改代码。
- **绑定层**：前端自定义组件只从已注册的 Metric Key 里选，组件不关心数据来自哪个服务。

成本约 200–300 行 Go + 一份 schema；收益是「用户自建组件不需要写脚本」，
同时安全边界清楚（不允许任意 URL / HTML）。

**已实现**：`http_json`（通用 GET+JSON，field_map 映射）、`jellyfin`（专用 /Sessions 解析）。
**仅设计**：Postgres / 进程 argv / Docker socket / SNMP 类 probe —— 接口已预留，但没写。

## 3. 服务不存在、服务挂了、服务在但字段变了

这是异构设备最容易翻车的地方，统一按三态处理：

| 情况 | 后端行为 | 前端表现 |
|---|---|---|
| 服务未配置 | 该 `now.<name>` 不存在 | 组件显示「无数据 · 该指标未上报，或服务未安装」 |
| 服务存在但请求失败 | `now.<name> = {ok:false, err:...}` | 显示「接口异常 / 断」，绝不空白 |
| 字段改名 / 版本差异 | 白名单映射取不到值 | 显示 `—` 并标注字段名，不猜、不编造 |
| 采样超时 | probe 独立超时，主循环照常 | 页面显示心跳变老 → 「连接中断」 |

关键原则：**采样失败不能拖垮采集主循环，也不能伪装成 0**。
`0` 表示「确实是 0」，「不知道」必须单独表达。

## 4. 首次体验：怎么做到「装完就是对的」

`/api/data` 顶层可选字段 `ui_hidden` 是为此加的：后端按实际启用的 probe 算出
不适用组件列表，前端**只在首次访问**（本机无布局偏好）时应用一次，之后完全尊重
用户拖拽结果。旧后端没有这个字段，行为不变（向后兼容）。

预设模板建议（**仅设计**，当前由安装者手动编辑 `hidden_widgets`）：

| 模板 | 显示 | 隐藏 |
|---|---|---|
| 纯系统 | CPU / 曲线 / 网络双轴 / eMMC / 温控 / 服务信号 | 所有 RK 硬件、Immich、Jellyfin 组件 |
| NAS | 纯系统 + 数据盘 + 磁盘 IO | RK 硬件、影音组件 |
| 影音中心 | 全部 | 无 |
| 纯 RK 开发板 | 全部 RK 硬件 + 系统 | 影音组件（若没装） |

## 5. 多架构与「不在设备上编译」

| 决策 | 理由 |
|---|---|
| Go 而非 Rust | armv6 是 Go 一等目标（`GOARM=6`），Rust 基本是 tier 3 |
| 纯交叉编译 | `CGO_ENABLED=0` + `GOOS/GOARCH/GOARM`，CI 的 Linux runner 直接出四份静态二进制 |
| **绝不碰 binfmt_misc / QEMU** | 之前在实体设备上注册二进制格式出过事故；模拟执行还会让 armv6 产物失去可信度 |
| 静态链接 | 绕开 glibc / musl / 老内核差异，部署只需一个文件 |
| 实机验证留给使用者 | CI 只能证明「能编译」和 `file` 输出正确，不能证明「在你的板子上跑得稳」 |

需要额外考虑但目前**仅设计**的：armv6 是否为 armv6l 硬浮点、老内核缺
`/sys/class/thermal`、无 systemd 的 OpenWrt/Alpine 上的服务托管、大端 MIPS。

## 6. 安全架构：能做什么、不能做什么

**不能**：让端口在局域网里「扫不到」。ARP / 端口扫描是二层事实，
port knocking / SPA 能增加隐蔽性，但要常驻额外守护进程或改防火墙，
与「最轻量」直接冲突，本项目放弃。

**能做**：扫到之后进不来。默认回环绑定 + 强制随机强密码 + 慢哈希加盐 +
失败限速/锁定 + 非 root + `ProtectSystem=strict` + 只读 GET + 去指纹。
剩下那一层（局域网/公网暴露）交给使用者自己的反代 + TLS，责任边界写进 README，
不假装内置 TLS 就万事大吉。

**凭据分层**（三类文件，权限与去向不同）：

| 文件 | 内容 | 权限 | 是否进仓库 |
|---|---|---|---|
| `config.json` | salt + 派生哈希、端点、字段白名单 | 0600 | ❌ |
| `*.token` | 第三方服务 API key | 0600 | ❌ |
| `web/index.html` | 纯前端，无任何凭据 | 0644 | ✅ |

前端自定义组件**不允许填 URL**是硬约束：否则一个「自定义组件」就能让服务端
去请求内网任意地址，Basic Auth 形同虚设。

## 7. 轻量化：省在哪里

| 手段 | 效果 |
|---|---|
| 单静态二进制内嵌前端 | 无 npm / 无 Vite / 无运行时依赖 / 无 CDN |
| 内存环形缓冲，历史不落盘 | 无数据库、无 IO、重启零残留 |
| 每 probe 独立低频 goroutine | 慢服务不拖慢 1 秒主采样 |
| 成功凭据缓存 60s | 避免每个请求重算 2 万轮派生（旧 Python 版实测 CPU 27% → 3.1%） |
| `/proc` 直读 | 单次 `/proc/net/dev` 实测 359 µs，1 秒采样约 0.036% CPU |
| systemd `MemoryMax` / `CPUQuota` | 异常时也封顶，不会把小设备拖死 |

目标是「一直开着」，所以**崩溃自愈**（`Restart=always`）、**超时不阻塞**、
**日志不写盘**比多两个花哨图表更重要。

**实测补充**（RK3568 / linux-arm64）：Go 版常驻 RSS 6.0 MB、空闲 CPU 0.6%、
单文件 5.3–5.6 MB，三项都优于上表目标。四架构交叉编译已在 `--network=none`
的临时容器里跑通（`go vet` 通过），编译完镜像与源码临时目录全部删除，
未触碰设备上任何已有容器或服务。这些数值只对这台板子成立，不外推。

## 8. 我没想周全、需要使用者补充的

- 不同发行版 `/sys` 路径差异（尤其 RK 系 VPU/NPU 节点、风扇 PWM）——通用版只读标准节点；
- 布局是否要跨设备同步：目前存 localStorage，手机和电脑各一套（**仅设计**：可加服务端布局端点）；
- 自定义组件的类型系统还比较弱（数值 / 文本 / 曲线），复杂单位换算靠约定；
- 配置版本迁移：`config.json` 目前无 `version` 字段，未来加字段靠缺省值兼容（**已实现**），
  破坏性变更需要单独的迁移脚本（**仅设计**）；
- 无障碍（键盘操作拖拽、读屏器标签）尚未系统验证。
